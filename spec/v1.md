# Native Blindfold contract, version 1

All binary lengths are unsigned 32-bit big-endian. Integers are unsigned big-endian. The envelope
contains, in order: length-prefixed UTF-8 canonical tenant ID; uint32 key version; uint64 policy ID;
algorithm byte 2; length-prefixed minimally encoded complete public exponent; length-prefixed
minimally encoded modulus; length-prefixed modulus-width wrapped block; AES-256-GCM ciphertext
followed by its 16-byte tag. The textual location is `string:///` followed by standard padded base64.

For policy ID `p` and exponent `e`, the effective exponent is `e * (2*p + 2^31 + 1)` without machine
integer truncation. Generate a random block of modulus byte width minus two. Set bytes 0 through 3
to `de ad be ef`. Bytes 4 through 15 are the GCM nonce and bytes 16 through 47 are the AES key. The
remaining bytes stay random. Wrap the unsigned block by modular exponentiation with the effective
exponent and modulus. Use empty GCM additional authenticated data. Encryption is randomized.

Inputs and public documents have a 2 MiB inclusive limit. Final encoded certificate and encrypted
locations, including their prefix, have a 131072-byte inclusive limit. Public RSA material must have
an odd 2048-8192-bit modulus, odd exponent greater than one and smaller than the modulus, and a
nonzero uint32 key version. Policy ID is a canonical decimal string within uint64. Public documents
must have one `data` object, equal canonical tenant IDs, no duplicate keys, aliases, merge keys,
multiple documents, float coercion, or conflicting root fields. Known camelCase names normalize to
snake_case; supplying both spellings is rejected. Base64 must be canonical.

Accept RSA 2048-8192 and EC P-256/P-384 private keys. Normalize keys to unencrypted PKCS#8 PEM.
Protected PKCS#8 and modern P12 are native inputs; P12 must contain exactly one private key. Reject
mixed sources, unmatched pairs, duplicate or unrelated certificates, invalid chain signatures, and
expired or future certificates. Locate the matching leaf and order supplied certificates leaf to
issuer using issuer names and signature verification. Serialize PEM with 64-column base64 and LF
line endings. A chain may omit its trust root. Check a supplied self-signed root signature.

Public identity fields are lowercase SHA256 hex: leaf DER fingerprint, SPKI DER identity, and
normalized chain PEM identity. Expiration uses UTC RFC3339. Context digest is SHA256 over canonical
JSON of the array `[public_document, policy_document]`, with recursively sorted object keys, known
aliases normalized, arrays in document order, and exact integer tokens. Preserve every public
policy field in that digest so a policy change rotates encryption.

The reserved `f5-sales-demo.com/blindfold` annotation is a JSON string of:

```json
{"version":1,"entries":{"default":{"chain":"sha256","spki":"sha256","context":"sha256","ciphertext":"sha256","algorithm":"RSA"}}}
```

Inline IDs must be explicit and unique within the resource. A named certificate defaults to
`default`. Ciphertext hash covers the exact UTF-8 encrypted location. Never record plaintext keys,
bundle bytes, passwords, or a private-key hash. Provenance is reconciliation metadata, not
attestation. Reuse only when its public identities and context match the requested normalized
inputs, and its chain and ciphertext hash match the actual remote material. Missing or malformed
provenance regenerates ciphertext. Reject an in-place RSA/EC algorithm change; require a new
certificate/reference cutover. Preserve unrelated metadata and resource options.

Terraform prepares available inputs during planning and encrypts only during apply. Write-only key
and bundle inputs require `material_version`; secret values never enter state or private state.
Persist public plan identities and reject changed normalized file material or refreshed context
when applying a saved plan. Refresh context during normal planning; changed context rotates once.
Unchanged inputs preserve ciphertext across process restart and sequential tool handoff. Import
does not recover private inputs. Observe remote private-key fields and repair drift. Carry the
server resource version into one mutation attempt; never retry conflicts. Reconcile accepted or
uncertain results by named readback. Concurrent ownership is unsupported.

Manifest ensure uses a top-level `x-xcsh-blindfold` object with `version: 1` and `certificates`, an
array of entries containing `id`, `pointer`, `certificate_file` and `private_key_file` or
`pkcs12_file`, optional `passphrase_env`, and `policy`. JSON pointers point to recognized certificate
nodes beneath `/spec`; reject unresolved, duplicate, or unsupported pointers. Remove the extension
before API serialization. Private values never enter assistant arguments or reports.
